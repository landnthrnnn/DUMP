CARTER / LANDON — LETHAL COMPANY FINAL SYNC PLAN
=================================================

PURPOSE
-------
Make Carter's Lethal Company Thunderstore profile match Landon's finalized
Default-extras setup as closely and reliably as possible.

Thunderstore handles the normal package installation first.

The Git-based passover then handles:
- Landon's finalized configuration tree
- local/custom media
- manually pruned packaged content
- local save data outside Thunderstore
- other files that a Thunderstore profile code cannot be trusted to reproduce


FINAL USER WORKFLOW
-------------------
1. Landon gives Carter the current Thunderstore profile code.

2. Carter imports that profile into Thunderstore Mod Manager.

3. Carter closes:
   - Lethal Company
   - Thunderstore Mod Manager / r2modman

4. Carter runs the standalone bootstrap PowerShell script.

5. The bootstrap:
   - checks whether Git for Windows is available
   - installs Git if needed
   - downloads only:
       misc\my-lethal-company-mod-setup
     from:
       https://github.com/landnthrnnn/DUMP
   - checks out the exact pinned Git commit containing the finalized payload
   - launches Install-Carter-Overlay.ps1

6. Install-Carter-Overlay.ps1:
   - verifies Carter has Default-extras
   - verifies all 399 expected Thunderstore packages
   - verifies exact package versions
   - verifies enabled/disabled states
   - verifies all payload SHA256 hashes
   - verifies the destination map
   - replaces the mapped directories/files
   - verifies the resulting destination contents/hashes

7. Temporary Git/download files may be deleted after successful completion.


NO BACKUP / ROLLBACK SYSTEM
---------------------------
There is intentionally NO backup or rollback layer.

The installer verifies prerequisites and payload integrity before making changes.

If verification fails before installation, installation stops.

If a filesystem/write failure occurs while applying the overlay, the script reports
the failure clearly but does not attempt to create or restore a backup.

TWO-COMMIT BOOTSTRAP DESIGN
---------------------------
The bootstrap should use an EXACT pinned Git commit so this setup remains
reproducible even if the DUMP repository changes later.

A script cannot contain the SHA of the same Git commit that contains that
script because adding/changing the SHA changes the commit SHA itself.

Therefore:

COMMIT 1
--------
Push:
- finalized passover-to-carter payload
- inventory
- plan
- expected-profile-state.json
- Install-Carter-Overlay.ps1
- NOTE.txt

Record Commit 1's SHA.


BOOTSTRAP GENERATION
--------------------
Generate Carter-Sync-Bootstrap.ps1 locally.

The bootstrap will contain Commit 1's exact SHA and use that SHA when
retrieving the finalized sync payload.


COMMIT 2
--------
Add Carter-Sync-Bootstrap.ps1 and perform one more normal commit/push.

Carter may receive/use the bootstrap from Commit 2, but the bootstrap itself
retrieves the immutable finalized payload from Commit 1.
